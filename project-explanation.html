Examiner Study Guide

Cold CRM

Complete technical explanation of the frontend, backend, database, authentication, integrations, scheduling, and deployment architecture.

Stack: Next.js 15, React 19, TypeScript, Tailwind CSS 4, Node.js, SQLite, SheetJS, Telegram Bot API

Repository: cold-crm

1. Project Overview

Cold CRM is an internal customer relationship management system for cold calling. A salesperson can manage potential customers, call them in a controlled order, record call results, schedule follow-ups and meetings, import leads from Excel or CSV, and receive Telegram notifications.

One-sentence description: Cold CRM is a full-stack Next.js application using React and Tailwind CSS for the interface, Next.js server features for the backend, SQLite with direct SQL for data storage, HMAC cookie authentication, Telegram notifications, and a server-side reminder scheduler.

4. Frontend Architecture

Server Components

Files in the app directory are Server Components by default. They execute on the server and can safely access the database and authentication cookies. The dashboard, lead list, meeting list, and detail pages query SQLite on the server before HTML is sent to the browser.

Client Components

A file containing "use client" runs in the browser. Client Components are necessary when the UI needs state, click handlers, or browser APIs.

  • CallScreen.tsx uses React state for the current lead, modal dialogs, loading state, history visibility, and clipboard feedback.
  • ImportClient.tsx reads files in the browser, previews rows, and sends the final data to the API.
  • NavBar.tsx uses usePathname() to highlight the active navigation link.

Frontend pages

  • Dashboard: statistics, funnel, upcoming meetings, and start-call button.
  • Call: lead card, phone action, call script, history, and outcome controls.
  • Leads: searchable and filterable lead table.
  • Lead detail: editing, call history, status, meetings, and reminders.
  • Meetings: complete, cancel, or reschedule meetings.
  • Import: upload, map columns, preview, and import spreadsheet data.

5. Backend Architecture

The backend is implemented inside the same Next.js project. There is no separate Express server.

Route Handlers

A route.ts file defines HTTP methods such as GET and POST. These handlers validate the request, check authentication, call business logic, and return a JSON or redirect response.

Server Actions

Functions marked with "use server" execute on the server and can be connected directly to HTML forms. The project uses them for creating and updating leads, adding reminders, changing status, and updating meetings.

Business logic

The main business logic is in lib/leads.ts. The key function is recordOutcome(). It coordinates the call record, lead status, next action, meetings, reminders, and Telegram notifications.

7. Database and SQL

The database is SQLite, created by lib/db.ts. On startup, the application creates the database directory, opens the file, enables SQLite options, and runs the schema creation statements.

Tables

TablePurpose
leadsStores customers, contact details, group, status, ratings, and next action.
callsStores every call attempt and its result.
meetingsStores planned meetings, location, notes, and meeting status.
remindersStores future follow-ups and meeting reminders.

Relational concepts used

  • Primary key: uniquely identifies each row, for example leads.id.
  • Foreign key: connects calls, meetings, and reminders to a lead.
  • Unique constraint: prevents duplicate main phone numbers.
  • Check constraint: restricts statuses and groups to valid values.
  • Indexes: speed up status, queue, call-history, and reminder queries.
  • JOIN: combines related rows, such as meetings with lead names.

Prepared statements

The project uses placeholders such as WHERE id = ? and passes values separately. This reduces SQL injection risk because user input is not concatenated directly into SQL strings.

SQLite WAL

PRAGMA journal_mode = WAL enables Write-Ahead Logging, which improves read/write behavior. PRAGMA foreign_keys = ON activates foreign-key enforcement.

8. Authentication and Middleware

The application uses one shared password from APP_PASSWORD in .env.local. The password is not stored in SQLite.

  1. The user submits the password to POST /api/login.
  2. checkPassword() compares it with the environment value.
  3. The server creates an HMAC-SHA256 token based on the password and session secret.
  4. The token is stored in an HTTP cookie named crm_session.
  5. Middleware checks this cookie on later requests.

Protected page requests redirect to /login. Protected API requests receive HTTP status 401. Logout removes the cookie.

Limitations: this is a small internal authentication system. It has one shared user, no roles, no password reset, and no individual accounts. A production multi-user system would normally use a full identity provider or a users table with hashed passwords.

9. Calling Queue and Business Rules

The queue algorithm is in lib/leads.ts.

  1. Due follow-up leads are selected first.
  2. The oldest due follow-up is selected first.
  3. If there are no due follow-ups, new leads are selected.
  4. New leads are prioritized by group A, B, C, then D.
  5. Within a group, older leads are selected first.
OutcomeSystem behavior
Did not answerSchedules tomorrow; after three consecutive failures, schedules seven days later.
Call laterStores selected time and creates a reminder.
InterestedSchedules tomorrow's follow-up and sends Telegram.
MeetingCreates a meeting, two reminders, and a Telegram message.
RejectedStores the reason and schedules another attempt after 90 days.
SoldMarks the lead as sold and sends Telegram.
Wrong numberRemoves the lead from the active queue.

10. Reminder System

There are two ways to process reminders, but both call the same function, processReminders().

  • Internal scheduler: Node.js starts a setInterval that checks every 60 seconds.
  • External cron: a service can call GET /api/cron/reminders.

Each reminder has a sent flag. Due unsent reminders are selected, processed, and then marked as sent. Rejected leads are returned to the queue; call and meeting reminders send Telegram messages.

11. Telegram Integration

The project uses the Telegram Bot HTTP API directly with fetch. It sends messages for interested leads, meetings, sales, and reminders.

Configuration uses:

TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...

If these variables are empty, the CRM continues working and only logs a warning. Messages use Telegram HTML formatting, so user text is escaped before being inserted into the message.

12. Import System

The browser uses SheetJS to read .xlsx, .xls, and .csv files. The first row is treated as headers. The application guesses columns by keywords such as “name”, “phone”, “address”, and their Uzbek or Russian equivalents.

After preview and manual mapping, the client sends JSON to /api/import. The backend then normalizes phone numbers, ignores rows without phones, ignores duplicate phone numbers, and returns an import report.

13. Time and Phone Utilities

Time

Times are stored in UTC in SQLite and displayed in Asia/Tashkent time. This prevents server timezone differences from changing the meaning of a meeting or follow-up.

Phone numbers

Phone numbers are normalized into the Uzbek format +998XXXXXXXXX. The system accepts common forms such as a nine-digit number, a leading zero, or a number containing spaces and punctuation.

14. Is There WebSocket or Realtime Technology?

No. The project does not use WebSockets, Socket.IO, Server-Sent Events, GraphQL subscriptions, or Firebase realtime listeners.

User clicks an outcome | v Browser sends POST /api/call/outcome | v Server updates SQLite and creates related records | v Server returns JSON containing the next lead | v React calls setData() and updates the screen

This is normal HTTP request-response communication. The reminder timer runs on the server, but it does not push data into an open browser tab.

15. Configuration and Running

Important scripts in package.json:

npm run dev       # development server with hot reload
npm run build     # optimized production build
npm start         # production server
npm run seed      # inserts sample leads

Important environment variables include APP_PASSWORD, SESSION_SECRET, DATABASE_PATH, Telegram variables, CRON_SECRET, and DISABLE_INTERNAL_CRON.

The project is designed for a continuously running Node.js machine or VPS because SQLite is local and the internal scheduler needs a persistent process.

16. Likely Examiner Questions

Why did you choose Next.js?

It provides React UI and backend features in one framework: routing, server rendering, API routes, middleware, Server Actions, and production builds.

Why SQLite?

The CRM is small and internal. SQLite is fast, simple, local, and does not require a separate database server.

Why TypeScript?

It catches invalid statuses, missing fields, and incorrect function arguments before runtime.

Why are some components Client Components?

The call and import screens need browser state, click handlers, file APIs, clipboard access, and client-side fetch requests.

How is authentication implemented?

A shared environment password is checked, then a signed HMAC token is stored in a cookie. Middleware checks the cookie on later requests.

How is SQL injection reduced?

Prepared statements use placeholders instead of concatenating untrusted values into SQL.

How are duplicate leads prevented?

The phone column has a UNIQUE constraint, and import logic checks existing numbers before inserting.

How are reminders executed?

An internal Node.js timer checks every 60 seconds, and an external cron endpoint can call the same reminder-processing function.

Is the application realtime?

No. It uses regular HTTP requests. After an action, the server returns updated data and React updates the page.

Why store times in UTC?

UTC is consistent on the server and in the database. The UI converts UTC to Asia/Tashkent for users.

What happens after a call result?

The call is saved, lead status is updated, follow-up or meeting records may be created, Telegram may be notified, and the next lead is returned.

What is the core business function?

recordOutcome() in lib/leads.ts, because it coordinates call history, statuses, reminders, meetings, and notifications.

What are the limitations?

There is one shared login, no user roles, no WebSockets, no automated test suite, and SQLite is not ideal for many concurrent users or multiple application servers.
